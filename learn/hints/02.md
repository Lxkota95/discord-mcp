# Hints — milestone 2

Read one hint, then go back and try again.

## Hint 1 (nudge)

Work in this order inside `parse`:
1. text → `Value` (failure: parse error, no id)
2. `Value` → JSON object (`Value::Object(map)`)
3. read `id` (it may be missing: that means notification)
4. check `jsonrpc == "2.0"`, then `method` is a string, then `params`
5. build `Incoming::Request` or `Incoming::Notification`

A small helper `fn invalid(id: Option<Id>, message: &str) -> Response` saves a lot of repetition.

## Hint 2 (stronger)

- `serde_json::from_str::<Value>(line).map_err(|_| Response::error(None, ErrorObject::new(PARSE_ERROR, "Parse error")))?`
- The id: `object.get("id")` is `Option<&Value>`. `None` → no id. `Some(raw)` → try
  `serde_json::from_value::<Id>(raw.clone())`; failure → invalid request with **no** id.
- `object.get("jsonrpc") != Some(&json!("2.0"))` checks both "missing" and "wrong".
- `params`: `None` is fine; `Some(Value::Object(_) | Value::Array(_))` is fine; anything else is
  invalid. A `match` with an `@` binding keeps the value: `Some(p @ (Value::Object(_) | Value::Array(_)))`.

## Hint 3 (almost the answer)

`to_value`:

```rust
let id = match &self.id { Some(id) => json!(id), None => Value::Null };
match &self.outcome {
    Ok(result) => {
        json!({ "jsonrpc": "2.0", "id": id, "result": result })
    }
    Err(error) => {
        json!({ "jsonrpc": "2.0", "id": id, "error": error })
    }
}
```

`json!(id)` works because `Id` derives `Serialize` (untagged, so it's just the number or string).
`error` serializes without `data` when it's `None`, thanks to `skip_serializing_if` on the field.
